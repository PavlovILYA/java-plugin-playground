# Plugin Playground — этап 1

Небольшой учебный проект для знакомства с контрактом плагина, а в следующих этапах — с Java SPI и `ClassLoader`. Сейчас консольное приложение показывает звёздное поле и корабль в бесконечной ASCII-анимации. Для выхода нажмите Ctrl+C.

## Модули и роли

- `plugin-api` содержит только интерфейс `AnimationPlugin`: имя плагина и метод, возвращающий готовый текстовый кадр.
- `plugin-host` содержит приложение и встроенный `StarfieldPlugin`.

`AnimationPlugin` — контракт SPI (Service Provider Interface): приложение определяет, какие действия должна предоставить реализация, а сама реализация может быть другой. На этом этапе это **контракт**, без механизма обнаружения провайдеров через `ServiceLoader`.

`StarfieldPlugin` вычисляет содержимое кадра и ничего не знает о терминале. `AnimationEngine` запрашивает кадры через `AnimationPlugin` примерно 12,5 раза в секунду. `TerminalRenderer` выводит полученный текст с ANSI-последовательностями: очищает экран один раз, перемещает курсор перед каждым кадром и возвращает его видимость при завершении. Над полем остаются имя плагина, способ подключения и загрузчик класса.

В `Main` реализация намеренно создаётся напрямую: `AnimationPlugin plugin = new StarfieldPlugin();`. Это самая простая отправная точка: видно, какой объект получает движок, и можно сравнить её с последующими способами подключения. `URLClassLoader` здесь ещё не нужен, потому что плагин находится в том же приложении. Позже можно будет изменить получение `AnimationPlugin` в `Main`, сохранив движок и рендерер.

## Сборка и запуск

Нужна JDK 21. Gradle устанавливать отдельно не требуется: в репозитории есть Wrapper.

```bash
./gradlew clean build
./gradlew :plugin-host:run
```

Размер сцены — 60×20 символов. Для заголовка и поля используйте терминал не менее 80×24 символов с поддержкой ANSI.

## Дальнейшие этапы

1. Внешний JAR: загрузка через `URLClassLoader` и reflection, при сохранении встроенного варианта.
2. `ServiceLoader`, `META-INF/services` и эксперименты с контекстным загрузчиком потока (TCCL).
3. Hot Swap внешнего плагина без перезапуска JVM и сравнение разных `ClassLoader`.

Каждый этап добавит новый способ подключения и сохранит предыдущие.
